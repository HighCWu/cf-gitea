# SPEC-0002: Authentication (users, personal access tokens, scopes, auth middleware)

Status: draft · Date: 2026-10-24 · Implements ADR-0001 decision D3 (D1 users/tokens) and
Tier-1 item "Gitea token auth semantics".
References: `docs/decisions/0001-technical-direction.md`, `specs/0001-storage-engine.md`
(R2/RepoDO boundary), `specs/0003-repo-lifecycle-git-http.md` (ACL matrix it consumes).
Upstream findings are cited against the vendored submodule (`gitea/`, read-only).

> **Version drift note.** ADR-0001 describes the submodule as "a v1.22-era dev commit".
> The actual pin is `v29.0.0-dev-208-gfc493688` (`git describe` in `gitea/`). All upstream
> findings below are from that checkout. The compat contract will be re-frozen at a stable

## 1. Problem and scope

cf-gitea is a headless Gitea: every request is authenticated the way the Gitea API and
git smart-HTTP clients authenticate. This SPEC defines identity (users in D1), credential
(personal access tokens), the scope model, the auth middleware behavior for `/api/v1` and
git HTTP, and the error shapes clients see.

In scope:

- D1 schema: `users`, `personal_access_tokens` (§3).
- Token format, hashing at rest, lookup, minting and revocation (§2.1–2.3, §3).
- Scope grammar and enforcement primitives, mapped to route categories (§2.4).
- Credential parsing: `Authorization: token X`, `Authorization: Bearer X`, HTTP Basic
  (token-as-password and token-as-username), and the sudo param/header (§2.2, §2.5).
- Middleware behavior matrix: 401 challenge vs 403 vs 404 for `/api/v1` and git HTTP (§2.6).
- Timing-safe comparison, per-IP failure-limiting hooks, throttled `last_used_at` (§2.7).
- OAuth2 provider endpoints and web session/CSRF — **documented only**, out of scope (§2.8).

Out of scope (later SPECs): `/api/v1` route bodies (0004), git HTTP routes and the repo
ACL matrix details (0003), password/SSO user sign-in (no password store exists yet; see
open questions), OAuth2 provider implementation, 2FA/WebAuthn, Actions task tokens,
HTTP-signature auth, admin API bodies (0004+).

## 2. Auth surface, with upstream behavior notes

### 2.1 Upstream token model (verified in source)

| Property | Upstream behavior | Source |
|---|---|---|
| Token value | 20 random bytes, hex-encoded → **40 hex chars**, returned to the caller exactly once | `gitea/models/auth/access_token.go:47–54` (`CryptoRandomBytes(20)` → `hex.EncodeToString`) |
| Storage | `TokenHash` (unique), `TokenSalt`, `TokenLastEight` (indexed); plaintext never stored | `access_token.go:20–34` |
| Hash at rest | **PBKDF2-HMAC-SHA256(token, salt, 10000 iters, 50-byte key), hex** — the `// sha256 of token` comment at `access_token.go:25` is stale; the real function is `HashToken` | `gitea/models/auth/twofactor.go:79–82` |
| Lookup | Rejects `len < 8`; `WHERE token_last_eight = ?` (non-unique index) then per-candidate PBKDF2 + constant-time compare (`util.CryptoConstTimeEqual`, `gitea/modules/util/util.go:97`); in-memory LRU of successful lookups | `access_token.go:90–127`, `gitea/models/auth/token_cache.go` |
| `last_used` | `UpdatedUnix` is rewritten **on every authenticated request** | `gitea/services/auth/basic.go:100–103`, `gitea/services/auth/oauth2.go:139–143` |
| Expiry | **No expiry field.** PATs never expire upstream (revocation = delete) | `access_token.go:20–34` |
| Credential checkers treat the token as an opaque string: `ParseAuthorizationHeader` splits scheme/value only; lookup needs `len ≥ 8` plus a last-8 index hint and a digest compare. No hex-40 assumption exists anywhere in the auth path. | | `gitea/modules/auth/httpauth/httpauth.go`, `access_token.go:90–127` |

The opaqueness claim is the load-bearing one for our format decision: the header parser
(`modules/auth/httpauth/httpauth.go`) treats the value as `parts[1]` verbatim; Basic auth
treats username-or-password as a whole string (`services/auth/basic.go:44–68`); the API
returns the minted token in a JSON field misleadingly named `sha1`
(`gitea/modules/structs/user_app.go:18`). Nothing client-visible parses the token body.

### 2.2 Credential parsing (compat surface)

`Authorization` header, case-insensitive schemes, exactly one space-separated value
(`modules/auth/httpauth/httpauth.go`):

- `token <value>` and `Bearer <value>` → bearer token (PAT, or an OAuth2 access token —
  upstream JWTs contain a `.`; we have none until the OAuth2 SPEC).
- `Basic base64(user:pass)` → `user` is tried as a token when `pass` is empty or
  `x-oauth-basic`; otherwise `pass` is tried as a token; failing that, real
  username/password sign-in (upstream: `services/auth/basic.go:44–68,124–167`).
  cf-gitea: token forms only (see divergences, §4.6).
- Query parameters `?token=` / `?access_token=`: upstream still accepts them **by default**
  (`DISABLE_QUERY_AUTH_TOKEN` defaults false, `gitea/modules/setting/security.go:224`),
  while the swagger marks them "deprecated for removal in Gitea 1.23" and sets an
  `X-Gitea-Warning` header (`routers/api/v1/api.go:930–934`, swagger meta `api.go:20–31`).
  cf-gitea: **not supported** (divergence, §4.6).
- `Sudo` header / `?sudo=` query: impersonation, admins only; non-admin → `403
  {"message":"Only administrators allowed to sudo."}`; unknown target → 404
  (`routers/api/v1/api.go:111–146`). There is **no "sudo" token scope** — the scope
  categories are exactly the nine in §2.4. Sudo swaps `ctx.Doer` but keeps the admin
  token's scope attached (`api.go:129–139`).
- `X-Gitea-OTP`: 2FA companion to Basic (upstream `services/auth/basic.go:169–187`).
  cf-gitea: accepted, no-op until a 2FA SPEC exists (no enrollment possible).

### 2.3 Token lifecycle API (compat surface)

- `POST /users/{username}/tokens` — create; requires signed-in **and** Basic-or-reverse-
  proxy auth (`reqToken` + `reqSelfOrAdmin` + `reqBasicOrRevProxyAuth`,
  `routers/api/v1/api.go:1069–1071`); duplicate name → `400 "access token name has been
  used already"`; invalid scope → `400 "invalid access token scope provided: …"`; empty
  scope → `400 "access token must have a scope"` (`gitea/routers/api/v1/user/app.go:77–150`).
- A token-authenticated request may only mint **child scopes it already holds**
  (`CanCreateChildScope`, `access_token_scope.go:310–321`; `403 "cannot create an access
  token with a broader scope than the authenticating token"`), and a `public-only` token
  cannot mint one that drops the restriction (`EnforcePublicOnlyFrom`,
  `access_token_scope.go:325–334`).
- `GET /users/{username}/tokens` (list, paged), `DELETE /users/{username}/tokens/{id}` —
  same auth guards (`api.go:1069–1071`).
- Response JSON (`modules/structs/user_app.go:12–27`):
  `{"id", "name", "sha1": "<plaintext token, returned once>", "token_last_eight",
  "scopes": [...], "created_at", "last_used_at"}`.

### 2.4 Scope model (compat surface)

Exact scope strings (`gitea/models/auth/access_token_scope.go:55–86`):

- Categories × levels: `read:` / `write:` over `activitypub`, `admin`, `misc`,
  `notification`, `organization`, `package`, `issue`, `repository`, `user`.
  `write:X` implies `read:X`.
- Modifiers: `all` (everything), `no-token-scope` (zero permissions), `public-only`
  (restriction: token may only see public orgs/repos; combinable).
- Grammar: comma-separated string, stored **normalized** (deduped, expanded, `all`
  collapsed) via a ≤64-bit bitmap (`access_token_scope.go:88–146, 235–290, 379–406`).
- Enforcement level comes from the HTTP method: POST/PUT/PATCH/DELETE ⇒ write, else read
  (`routers/api/v1/api.go:271–305`).
- Route→category wiring upstream (`tokenRequiresScopes(category...)` across
  `routers/api/v1/api.go`): repository ×8, organization ×4, issue ×4, user ×5 (incl. the
  combined `user+organization`), notification ×2, package, admin, activitypub ×1.
  `misc` is registered nowhere in this checkout (placeholder, `access_token_scope.go:20`).
- Git HTTP enforces the `repository` category at read/write level via
  `CheckRepoScopedToken` (`gitea/services/context/permission.go:16–34, 78–81`); missing
  scope there is a **plain 403**, not JSON.
- Admin visibility: `DoerIsSiteAdminFullAccess` requires a non-public-only admin token
  whose scope is absent or `all` (`gitea/models/user/user_extdata.go:110–115`).

cf-gitea implements the same grammar verbatim (parser + normalizer as a unit-tested
module, §5) and the same category→route-group mapping for the route groups SPEC-0004
declares. `activitypub` routes do not exist → the scope is parsed but never granted by a
route. `misc` is parsed but likewise never required.

### 2.5 Auth middleware chain (design)

Mirroring upstream's group (`buildAuthGroup`, `routers/api/v1/api.go:849–857`: OAuth2 →
HTTPSign → Basic, optional reverse-proxy) reduced to cf-gitea's reality:

1. Parse `Authorization` (§2.2). Bearer value → PAT lookup; Basic → token forms (§2.2),
   real-password sign-in deferred (open question).
2. PAT found, active, unexpired → doer = token owner, `scope` attached, `isBasicAuth`
   true when it arrived via Basic.
3. No credentials → anonymous doer (routes decide anon-allowance).
4. Credentials present but invalid → `401 {"message":"invalid username, password or
   token","url":…}` (`apiAuth`, `api.go:862–875`).
5. Post-auth option checks (mirrors `verifyAuthWithOptionsAPI`, `api.go:877–920`):
   prohibited/unactivated account → `403 {"message": …}`; then route middlewares
   `reqToken` (401 `"token is required"`), `tokenRequiresScopes` (403 scope message),
   `reqSiteAdmin`/`reqOwner`/`reqAdmin`/`reqSelfOrAdmin` (403), `sudo()`.

### 2.6 Behavior matrix (401 vs 403 vs 404)

`/api/v1` (JSON; error body `{"message": string, "url": string}` — upstream `APIError`,
`gitea/services/context/api.go:64–67, 137–155`; `url` = the instance swagger URL):

| Situation | Status / body | Source |
|---|---|---|
| No credentials on a token-required route | `401 {"message":"token is required", …}` | `api.go:305–311` |
| Bad/expired/revoked credentials | `401 {"message":"invalid username, password or token", …}` | `api.go:862–875` |
| Valid token, missing scope | `403 {"message":"token does not have at least one of required scope(s), required=[…], token scope=…", …}` | `api.go:299–303` |
| Non-admin uses `sudo` or admin route | `403 {"message":"Only administrators allowed to sudo."}` / `"user should be the site admin"` | `api.go:140, 343–347` |
| `RequireSignInViewStrict` and anonymous | `403 {"message":"Only signed in user is allowed to call APIs."}` | `api.go:903–907` |
| Private repo / hidden user, anonymous or insufficient | **404** `{"message":"not found", …}` (existence not disclosed) | `individualPermsChecker` `api.go:922–927`, `APIErrorNotFound` |
| Public repo, anonymous | 200 (anon-allowed route group) | route registrations |

git HTTP (`/{owner}/{repo}(.git)?/info/refs|git-upload-pack|git-receive-pack`; bodies are
**plain text**, not JSON — upstream `gitea/routers/web/repo/githttp.go:80–260`):

| Situation | Response | Source |
|---|---|---|
| Anonymous fetch of public repo (public owner) | 200 protocol response | `githttp.go:130–144` |
| Anonymous, anything else | `401` + `WWW-Authenticate: Basic realm="Gitea"` (realm exact string matters: GCM then attempts its built-in OAuth2 app) | `githttp.go:146–159` |
| Wrong credentials | 401 (auth group error) | `apiAuth` semantics |
| Valid token, missing `read:repository`/`write:repository` | plain **403** | `gitea/services/context/permission.go:16–34` (call `githttp.go:163`) |
| Authenticated, no repo permission | plain **404** `"Repository not found"` | `githttp.go:198` |
| Nonexistent repo, fetch | plain **404** `"Repository not found"` (after auth check) | `githttp.go:209–216` |
| Nonexistent repo, push | 404 unless push-create enabled (SPEC-0003 owns this) | `githttp.go:209–250` |
| Disabled/prohibited account | plain **403** `"Your account is disabled."` | `githttp.go:180–182` |

Alignment rule (with SPEC-0001/0003): private repo + anonymous/underprivileged ⇒ **404**,
never 403/401-with-existence-leak; 401 only as an authentication *challenge*; 403 only
for authenticated principals lacking scope/admin.

### 2.7 cf-gitea middleware mechanics

- **Timing-safe comparison**: sha256 digests compared via Workers'
  `crypto.subtle.timingSafeEqual` (both arguments equal length — compare 32-byte
  digests, never hex strings of differing length). Upstream equivalent:
  `util.CryptoConstTimeEqual` (`modules/util/util.go:97`).
- **Lookup**: `WHERE prefix = ?` on the unique prefix index — one D1 row read, one
  digest compare (upstream: last-8 fan-out + per-candidate PBKDF2, §2.1).
- **Failure limiting** (no upstream equivalent — enhancement): per-IP+route failure
  counter in D1 (`auth_failures`, §3) inside the auth service; ≥20 failures in a sliding
  5-min window ⇒ API `429` with `Retry-After`, git HTTP `403` plain text (no
  `WWW-Authenticate`, so credential prompts stop). Success clears the counter. Kept as a
  `RateLimitHook` interface so it can move to a DO/KV backend without touching callers.
  Workers isolates have no shared memory, so the counter must be in D1 (or a DO) from
  day one.
- **`last_used_at` throttling**: updated at most once per 24 h per token (planned
  `waitUntil` write; upstream rewrites on every request, §2.1). Write amplification on
  D1 (row writes ≈ $1/M) makes per-request updates wasteful; the API field granularity
  (day) is unaffected.

### 2.8 Documented-only upstream areas (Tier 2 / later)

- **OAuth2 provider**: `/login/oauth/authorize` (GET/POST, signed-in), `/login/oauth/grant`
  (POST), `/login/oauth/userinfo` (GET/POST), `/login/oauth/access_token` (POST),
  `/login/oauth/keys` (GET, OIDC JWKS), `/login/oauth/introspect` (POST)
  (`gitea/routers/web/web.go:617–631`). Implementation deferred to a later SPEC; token
  auth must already accept Bearer values so the endpoint can slot in.
- **Web sessions**: cookie `gitea_session` (`gitea/modules/setting/session.go:36,61`),
  remember-me tokens are `id:secret` pairs with sha256-at-rest and rotation
  (`gitea/services/auth/auth_token.go:33–121`). Session auth never applies to `/api/v1`
  in the pinned checkout (§2.5 — no session method in the API auth group), which matches
  the ADR-0001 finding that the official UI does not call the API.
- **CSRF**: this dev line has **dropped** the CSRF token upstream — only a FIXME remains
  (`gitea/services/context/context.go:179–180`). Any Tier-2 HTML work (SPEC-0006) must
  re-check upstream state at its pin; nothing to build for Tier 1.

## 3. Data model

Drizzle schema (`src/db/schema.ts`), D1. Conventions: unix-second timestamps
(`integer` + `mode: 'timestamp'`); booleans as `integer({ mode: 'boolean' })`.

```ts
import { sqliteTable, integer, text, uniqueIndex, index } from 'drizzle-orm/sqlite-core';

export const users = sqliteTable('users', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  /** Display-cased username, as Gitea's `name`. */
  username: text('username').notNull(),
  /** Case-folded login key; mirrors upstream `lower_name` UNIQUE
   *  (gitea/models/user/user.go:97) — all lookups are case-insensitive. */
  usernameLower: text('username_lower').notNull(),
  email: text('email'),
  displayName: text('display_name'),
  /** Site admin — gates `sudo`, admin routes (upstream `IsAdmin`). */
  isAdmin: integer('is_admin', { mode: 'boolean' }).notNull().default(false),
  /** 'active' | 'prohibited' — upstream `IsActive` / `ProhibitLogin`
   *  (gitea/routers/web/repo/githttp.go:194–197). */
  status: text('status', { enum: ['active', 'prohibited'] }).notNull().default('active'),
  createdAt: integer('created_at', { mode: 'timestamp' }).notNull(),
}, (t) => [uniqueIndex('users_username_lower_uq').on(t.usernameLower)]);

export const personalAccessTokens = sqliteTable('personal_access_tokens', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  userId: integer('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  /** Caller-chosen label; duplicate-per-user rejected at the service layer,
   *  matching upstream's non-constraint check (access_token.go:130–132). */
  name: text('name').notNull(),
  /** 'cfg_<8hex>' — public lookup key, UNIQUE index for O(1) resolution.
   *  Plays the role of upstream's non-unique `token_last_eight`. */
  prefix: text('prefix', { length: 12 }).notNull(),
  /** hex(sha256(full token value)); plaintext never stored. */
  sha256Digest: text('sha256_digest', { length: 64 }).notNull(),
  /** Normalized, comma-joined upstream scope string (§2.4). */
  scopes: text('scopes').notNull(),
  lastUsedAt: integer('last_used_at', { mode: 'timestamp' }),
  /** cf-gitea extension: upstream PATs never expire (§2.1); null = no expiry. */
  expiresAt: integer('expires_at', { mode: 'timestamp' }),
  createdAt: integer('created_at', { mode: 'timestamp' }).notNull(),
}, (t) => [
  uniqueIndex('pat_prefix_uq').on(t.prefix),
  index('pat_user_idx').on(t.userId),
]);

/** Per-IP auth-failure window (§2.7). One live window per IP; `count` is
 *  upserted, reset on success or window rotation. */
export const authFailures = sqliteTable('auth_failures', {
  ip: text('ip').notNull().primaryKey(),
  windowStart: integer('window_start', { mode: 'timestamp' }).notNull(),
  count: integer('count').notNull().default(0),
});
```

**Token format decision.** `cfg_<8hex>_<32base32>` — `cfg_` literal, 8 hex chars
(collision-retried unique prefix, see below), `_`, 32 chars of base32 over the alphabet
`ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (160 bits; the unambiguous alphabet matches upstream's
two-factor generator, `models/auth/twofactor.go:70–75`). Secret entropy = 160 bits,
identical to upstream's 20 random bytes. Full length 45 chars (≥ upstream's 40; the only
upstream length gate is `len ≥ 8`, `access_token.go:91`).

**Opaque-prefix vs exact 40-hex — decided: opaque prefixed.** Verified compat argument:
clients treat tokens as opaque strings end-to-end (§2.1 table row 8) — header parsing,
Basic username/password forms, credential helpers (`tea`, git credential managers), and
the `sha1` response field all pass the value through verbatim. No hex-40 assumption
exists in the upstream auth path. The prefixed format buys O(1) D1 lookup (durable-git /
git-on-cloudflare pattern, ADR-0001 D3: "SHA-256 digest + unique prefix"), instant visual
identification (`cfg_` vs upstream hex), and independence from upstream format churn at
the re-pin. Cost: `token_last_eight` in API responses shows the last 8 chars of *our*
format (opaque to UI, acceptable); prefix collisions (32-bit space) retry generation up
to 3 times on unique-constraint violation (birthday risk at 10k tokens ≈ 1%, retried
away). Ingest of pre-existing 40-hex Gitea tokens (migration/import path, later SPEC):
store their sha256 digest with prefix = first 12 chars of the hex — the resolver accepts
both shapes. **`token_last_eight` note (implementation 2026-10-24):** the schema has no
separate last-8 column; the API field derives from the token's own public prefix —
the 8 hex chars of `cfg_<8hex>_` — which is visible in the plaintext at mint and list
time and stable across both formats.

**Hashing decision.** sha256(full token) hex at rest, diverging from upstream's PBKDF2
(§2.1). Justification: PBKDF2-HMAC-SHA256 at 10 000 iterations per *request* is a
meaningful CPU cost on Workers (300 s CPU ceiling but per-request latency/bill matter),
defended only against brute-force of low-entropy secrets; our secrets carry 160 bits of
crypto-random, where sha256 preimage resistance is not the weak link. Digest comparison
is timing-safe (§2.7). If a future feature lets users choose weak tokens (none planned),
salting/PBKDF2 gets revisited for that path only.

## 4. Edge cases, limits, failure modes

### 4.1 Credential states

| State | Behavior |
|---|---|
| Expired token (`expires_at` past) | Treated as unknown credential → 401 `"invalid username, password or token"` (API) / 401 challenge (git). No scope-leaking "expired" message (upstream has no expiry; divergence §4.6). |
| Revoked (deleted) token | Same as unknown credential; in-flight requests fail on next lookup (no cache in cf-gitea v1 — upstream's LRU re-validates against D1 anyway, `access_token.go:97–109`). |
| Malformed `Authorization` (bad base64, 3 fields, unknown scheme) | Parsed as *no credentials* (upstream `ParseAuthorizationHeader` returns `!ok`) → anonymous → 401 per matrix. |
| Basic with valid username + wrong password | 401 (password sign-in deferred — the attempt still counts against failure limiting). |
| Prefix exists, digest mismatch | Timing-safe compare still runs against the looked-up digest; failure counted per IP. |
| `public-only` token | All private org/repo reads 404-masked (upstream `IsPublicOnlyDoer`/`DoerCanViewPrivate`, `models/user/user_extdata.go:98–117`); enforced in repo-visible layer (SPEC-0003/0004), auth only carries the flag. |

### 4.2 Sudo

`sudo`/`Sudo` resolves target by name (case-insensitive); target missing → 404;
requester not admin → 403 `"Only administrators allowed to sudo."`; the swapped doer
keeps the *admin token's* scope (upstream `api.go:129–139`) — so an `admin`-scoped token
sudoed onto a user still cannot exceed its scopes. Audit trail: cf-gitea records
impersonation in the audit log (ADR-0001 D3) when that table lands (0004+).

### 4.3 Scope edge cases

- `all` normalizes to the literal string `all`, not the expanded list (upstream
  `toScope`, `access_token_scope.go:399–405`); `no-token-scope` authenticates the user
  but grants zero permissions (every scoped route 403s).
- Unknown scope strings are rejected at creation with upstream's 400 message; never
  silently normalized away (`Normalize` errors, `access_token_scope.go:281–290`).
- Trailing commas / empty segments tolerated (upstream parser skips empties,
  `access_token_scope.go:240–267`).
- write⇒read implication is baked into the bitmap at parse time; enforcement checks
  `HasScope(required)` — write tokens satisfy read requirements.

### 4.4 Limits

- Token name ≤ 255 chars; ≤ 255 chars otherwise enforced at API layer (0004).
- Failure window: 20 failures / 5 min / IP (jittered +0–20% to avoid trivially detecting
  the threshold); counter cleared on success; git HTTP uses plain 403 (no challenge).
- `last_used_at` write at most once per token per 24 h.
- Per-request D1 reads for auth: 1 (token) + 0 (user cached in the same row join).

### 4.5 Failure modes

- D1 unavailable → auth returns 500 (upstream `APIErrorInternal` shape); git HTTP plain
  500. Never fail open.
- Prefix-unique violation during minting → retry ≤ 3, then 500 (astronomically unlikely).
- Clock: `expires_at` comparisons use request time from the Workers runtime.

### 4.6 Intentional divergences from upstream (complete list)

1. **Token format**: opaque `cfg_<8hex>_<32base32>` vs 40-hex (wire-compatible, §3).
2. **Hash at rest**: plain sha256 vs salted PBKDF2-HMAC-SHA256/10k (§3).
3. **Lookup**: unique prefix index vs last-8 non-unique index + candidate scan (§2.7).
4. **PAT expiry**: `expires_at` added; upstream has none (§2.1, §3).
5. **`last_used_at`**: 24 h throttle vs per-request update (§2.7).
6. **Query-string auth** (`?token=`, `?access_token=`): not supported; upstream still
   accepts by default in the pinned commit but deprecated it for 1.23+ (§2.2).
7. **Basic real-password sign-in**: deferred (no credential store SPEC yet); Basic is
   token-forms-only until then (§2.2) — Git/GCM token flows unaffected.
8. **No OAuth2 bearer JWTs** until the OAuth2 SPEC (values containing `.` are simply
   invalid PATs → 401, matching "not found" behavior).
9. **No HTTPSign / reverse-proxy / SSPI auth** (upstream API group extras, §2.5).
10. **No 2FA**; `X-Gitea-OTP` accepted, ignored (§2.2).
11. **Per-IP failure limiting added** — no upstream equivalent (§2.7).
12. **No Actions runner/task tokens** until the Actions compat SPEC.

Non-divergences (kept byte-compatible): error JSON shapes and messages (§2.6 table),
scope grammar and normalization, git HTTP challenge realm and plain-text bodies, token
CRUD guards and messages, sudo semantics.
