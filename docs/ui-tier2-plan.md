# Tier-2 UI feasibility plan: reusing vendored Gitea frontend assets without Go

Status: **research complete — feasible, proven by build** · Date: 2026-10-24.
Implements ADR-0001 decision **D2 Tier 2** (serve pages that reuse Gitea's built
assets with our own server-rendered Hono JSX HTML). Feeds the future
`specs/0006-ui-tier2.md`.
Evidence base: the `gitea/` submodule at pin `fc49368845` (`v29.0.0-dev-208-gfc49368845`)
plus a real standalone frontend build run (§3). Every number below was produced by a
command recorded in this document, not estimated.

## 1. Verdict

**The vendored Gitea frontend builds standalone, with zero Go, in ~2–3 seconds, and
emits a 784-file / ~13.9 MB deployable asset tree with content-hashed filenames and a
Vite manifest our Hono JSX can resolve directly.** The Tier-2 strategy is viable as
specified. The DOM/CSS/JS contract our pages must satisfy is small and mechanical
(§4); the first three pages are almost fully covered by SPEC-0004 tier-1 endpoints,
with five concrete data gaps (§6).

Key surprise vs the ADR's description of upstream ("Fomantic-UI/jQuery"): at this pin
upstream has **already deleted Fomantic-UI CSS** — `web_src/css/index.css` imports
Gitea-owned "fomantic replacements" (`web_src/css/modules/*.css`). Fomantic survives
only as a 2-file JS hard-fork (api + dropdown) plus a jQuery 4 global, pre-bundled in
the `iife.js` block script. No webpack, no gulp — the pipeline is a single
`pnpm exec vite build` (Vite 8 / rolldown).

## 2. Asset pipeline at this pin

### 2.1 Build system

- `gitea/vite.config.ts` — Vite 8.3.4 (rolldown-vite), `appType: 'custom'`
  ("Go serves all HTML, disable Vite's HTML handling"). Output dir is hard-coded to
  `<repo>/public/assets`; `emptyOutDir: false`; base `'./'`.
- Makefile: `make frontend` = `pnpm install --frozen-lockfile` + `rm -rf
  public/assets/{js,css,fonts,.vite}` + `pnpm exec vite build`. Targets
  `FRONTEND_DEST = public/assets/.vite/manifest.json` — the manifest is the
  freshness marker. `make frontend` itself never invokes Go.
- Entrypoints (`rolldownOptions.input`): `web_src/js/index.ts` (the main module),
  `swagger.ts`, `external-render-frontend.ts`, `user-events.sharedworker.ts`,
  `web_src/css/devtest.css`, and every `web_src/css/themes/*.css` (9 themes at this
  pin). Two additional blocking IIFE bundles are built by a custom plugin:
  `web_src/js/iife.ts` (jQuery + Fomantic hard-fork) and
  `web_src/js/external-render-helper.ts`; both are appended into the same manifest.
- Output naming: `js/[name].[hash:8].js`, `css/[name].[hash:8].css`,
  `fonts/[name].[hash:8].[ext]` (no fonts were emitted — all font URLs are inlined
  as data URLs under the 32 KiB `assetsInlineLimit`).
- CSS pipeline: PostCSS + Tailwind 3 (`tailwind.config.ts`, prefix `tw-`,
  `important: true`, content scans `templates/**/*.tmpl` and `web_src/js/**`).
  Tailwind config only **reads** the two base theme CSS files at config-load time;
  it needs no Go.

### 2.2 Fomantic-UI status (corrects the ADR's mental model)

- `web_src/css/index.css` imports `./modules/*.css` commented "fomantic replacements"
  (button, container, menu, dropdown, table, …) — all Gitea-owned CSS implementing
  the `.ui.*` class vocabulary.
- `web_src/fomantic/build/fomantic.js` is a **vendored hard-fork of Fomantic UI
  2.8.7** containing only `api.js` + `dropdown.js` ("GITEA-PATCH" comments); it is
  committed source, not a build product. It is imported first by
  `web_src/js/index.ts`.
- `web_src/js/globals.ts` sets `window.$ = window.jQuery = jquery` (jQuery 4.0.0,
  bundled). `web_src/js/modules/fomantic.ts` patches dropdown behavior at init time.

## 3. Proof: standalone build without Go

Commands actually run (outside the repo, at `/tmp/gitea-assets-build`, tool versions
`node v25.9.0`, `pnpm 12.13.0`):

```sh
mkdir /tmp/gitea-assets-build && cd /tmp/gitea-assets-build
cp -r <repo>/gitea/web_src <repo>/gitea/public .            # 2.9 MB + 2.3 MB
mkdir tools assets
cp <repo>/gitea/tools/shared.ts tools/
cp <repo>/gitea/assets/* assets/                            # incl. go-licenses.json
cp <repo>/gitea/{package.json,pnpm-lock.yaml,pnpm-workspace.yaml,vite.config.ts,tailwind.config.ts} .
pnpm install --frozen-lockfile        # Done in 2.3s (cold store share), zero postinstalls
pnpm exec vite build                  # NODE_ENV unset => production mode
```

Results:

- First run failed with exactly one missing input
  (`UNRESOLVED_IMPORT: Could not resolve '../../../../assets/codemirror-languages.json'
  in web_src/js/modules/codeeditor/main.ts`) — fixed by copying the committed
  `assets/` dir. After that: **`✓ 2606 modules transformed. ✓ built in 2.49s`** —
  no Go toolchain present, no generated-file errors.
- A repeat build with `ENABLE_SOURCEMAP=false` (the deploy setting) also succeeded;
  `find public/assets -name '*.map' | wc -l` = 0.

## 4. DOM/CSS/JS contract for our Hono JSX

Our JSX must emit the skeleton below so the unmodified bundles apply and enhance.
Sources: `templates/base/head.tmpl`, `head_style.tmpl`, `head_script.tmpl`,
`base/head_navbar.tmpl`, `base/footer.tmpl`, `templates/repo/{home,header,view_list}.tmpl`,
`templates/repo/commits_table.tmpl`.

### 4.1 Page skeleton

```
<html lang="en" data-theme="gitea-light">
<head>
  <link rel="stylesheet" href="/assets/css/index.<h8>.css">        <!-- AssetCSSLinks("web_src/js/index.ts","web_src/css/index.css") -->
  <link rel="stylesheet" href="/assets/css/theme-gitea-light.<h8>.css">  <!-- ctx.CurrentWebTheme.PublicAssetURI -->
  <link rel="icon" href="/assets/img/favicon.svg" type="image/svg+xml">
  <script>window.addEventListener('error', ...push to _globalHandlerErrors...)</script>
  <script type="application/json" id="global-window-config">{...window.config, §4.3}</script>
  <script src="/assets/js/iife.<h8>.js"></script>                  <!-- blocking; defines window.$/jQuery -->
</head>
<body>
  <div class="full height">
    <nav id="navbar" aria-label="Navigation bar"> … </nav>          <!-- §4.2 -->
    <div role="main" aria-label="{title}" class="page-content repository file list">
      … page body …
    </div>
  </div>
  <footer>…footer_content…</footer>
  <script type="module" src="/assets/js/index.<h8>.js"></script>    <!-- last elem of body -->
</body>
</html>
```

Notes: `AssetCSSLinks` expands (via the manifest) to the entry CSS **plus the CSS of
every statically-imported chunk** — for `index.ts` that is the single
`css/index.<h8>.css`. The theme `<link>` is resolved through the same manifest from
`web_src/css/themes/theme-<name>.css` (`services/webtheme/webtheme.go`). The `#navbar`
element is optional (install page omits it) but expected on every app page.

  `.page-content` (+ page discriminator classes: `repository`, `file list`, `blame`),
  `.ui.container`, `.ui.menu/.secondary.pointing.menu`, `.ui.button/.label/.segment/

  `.flex-left-right`, `.not-mobile`/`.only-mobile`, `.muted`/`.muted-links`,

- Repo nav: `div.secondary-nav > div.ui.container > div.repo-header.flex-left-right`,
  then `.ui.container > overflow-menu.ui.secondary.pointing.menu >
  .overflow-menu-items > a.item(.active)` (code/issues/pulls/releases/… tabs with
  `data-shortcut-keys="g c"` etc.), closed by `.ui.tabs.divider`.
- Repo home file list: `#repo-files-table` (a CSS-grid container; the ID is
  load-bearing — "many other CSS styles depending on this ID") with children

- Icons are **inline SVGs** (`{{svg "octicon-x" 16}}` → inlined `<svg class="svg
  octicon-x">`); our JSX inlines the same committed `public/assets/img/svg/*.svg`

### 4.3 `window.config` and the JS init model

Our pages must include `<script type="application/json" id="global-window-config">`
with (from `services/context/context_template.go WindowConfig()`):

```
{ appUrl, appSubUrl, assetUrlPrefix: "/assets", runModeIsProd: true,
  customEmojis, pageData: {…per-page JSON payload…},
  mermaidMaxSourceCharacters, sharedWorkerUri: "/assets/js/user-events.sharedworker.<h8>.js",
  notificationSettings: {…}, i18n: {7 general keys: error_occurred, remove_label_str,
  modal_confirm, modal_cancel, more_items, copy_success, copy_error} }
```

Initialization is **not** `DOMContentLoaded`-driven: the `type="module"` index.js
executes after HTML parsing and runs ~80 `init*` functions, then
`initGlobalSelectorObserver()`, then sets `window.config.frontendInited = true`
(the footer template alerts if that flag is missing in prod). Enhancement hooks our
HTML must provide:

1. `data-global-init="<name>"` — per-element init registry
   (`modules/observer.ts`), e.g. `data-global-init="initRepoSwitcher"` on the repo
   dropdown in the header. A MutationObserver keeps handling SPA-morphed nodes.
2. `data-global-click="<name>"` — delegated click actions; plus conventions
   `data-url` on `.link-action` buttons, `data-tooltip-content` (tippy),
   `data-shortcut-keys`, `data-fetch-url`/`data-fetch-trigger="load"`/
   `data-fetch-sync="$morph"` (idomorph-based partial refresh, used by
   `#repo-files-table` when directory commits are not all resolved).
3. Selector handlers — most importantly `.ui.dropdown:not(.custom)` initializes the
   jQuery/Fomantic dropdown behavior; our JSX emits plain
   `<div class="ui dropdown">…<div class="menu">` structures and the bundle wires
   them up.
4. Web components (custom elements the Vue compiler passes through):
   `<overflow-menu>`, `<relative-time>` (Gitea-owned) and `<markdown-toolbar>`,
   `<text-expander>` (deps). All are inside index.js — nothing extra to serve.
5. Vue islands mount into elements the `initComp*/initGlobalComponent` functions
   find (e.g. contributors/code-frequency charts mount into placeholder divs); our
   pages include the same placeholder elements + `pageData` keys when we adopt them.

### 4.4 Asset URL resolution — we reuse the manifest, not Go

`modules/public/manifest.go` is the entire Go-side mechanism: parse
`assets/.vite/manifest.json`, map `web_src/js/index.ts` → `js/index.<h8>.js`, and
walk `imports` for CSS links. Our Hono JSX replicates this in ~40 lines of TS:
load `apps/worker/public/assets/.vite/manifest.json` at module init (per isolate),
then `assetURI("web_src/js/index.ts")` and `assetCssLinks("web_src/js/index.ts")`
produce exactly what the templates produce. Hashes change only on re-pin/rebuild,
so the manifest can be cached for the isolate lifetime.

## 5. Serving plan

- **Location**: build output lands at `apps/worker/public/assets/`
  (gitignored; see below). `wrangler.jsonc` (orchestrator-owned) gains:

  ```jsonc
  "assets": {
    "directory": "./public",
    "run_worker_first": ["/api/*"]   // gitorange pattern per SPEC-0004
  }
  ```

  Default routing is assets-first / worker-on-miss: every HTML route, git smart-HTTP
  route and `/api/v1` route 404s against the asset tree and falls through to the
  Worker, so only `/api/*` strictly needs `run_worker_first`. Git paths
  (`/{owner}/{repo}.git/…`) never collide with asset paths, but the Worker **must
  reserve the owner name `assets`** in the D1 registry (upstream reserves it too) so
  `/assets/…` can never be a repo path. Serving HTML through the Worker and letting
  the edge serve `/assets/*` directly keeps Worker invocations (and CPU) off the
  static hot path; `env.ASSETS.fetch()` remains available for any programmatic need.
- **Capacity**: 784 files / 13.9 MB total, largest file 1.47 MB (`swagger` lazy
  chunk) — far under Workers Static Assets limits (20,000 files free / 100,000 paid
  per Worker version, 25 MiB per file). Serving `/assets/*` from the edge is
  free of Worker request charges and egress is unmetered.
- **Cache headers**: all bundle filenames carry an 8-char content hash. Serve
  `Cache-Control: public, max-age=31536000, immutable` for `/assets/js/*`,
  `/assets/css/*`, `/assets/fonts/*` via a `_headers` file inside the assets
  directory; the manifest, `emoji.json`, `img/*` and `licenses.txt` get short TTLs
  (`max-age=3600`) since they are not hash-named (the manifest must stay fresh for
  re-pins).
- **Build integration**: a repo-level script `pnpm build:assets` calling
  `scripts/build-gitea-assets.mjs` (this repo's only new tool file, §7) which
  copies → installs → builds → emits into `apps/worker/public/assets`. `pnpm build`
  (vite/worker build) does not depend on it; deploy docs instruct
  `pnpm build:assets && pnpm deploy`.
- **Committed vs rebuilt — recommendation: gitignore the output, rebuild on demand.**
  Reasons: (a) 784 files / ~14 MB of derived artifacts contradict the AGENTS.md rule
  "generated artifacts are never committed" (`dist/`, `dist-types/` precedent);
  (b) reproducibility does not need committed blobs — the submodule pin (D5) +
  committed `pnpm-lock.yaml` + content-hashed outputs make CI builds deterministic
  (the whole pipeline is ~3 s of build after a warm pnpm store); (c) LFS adds
  infrastructure (and Cloudflare-hosted git is *our own product*) for zero benefit;
  (d) a stale committed tree would silently shadow a re-pin — the exact failure
  ADR-0002 wants to avoid. CI adds a guard: build fresh and diff the emitted
  manifest against a `wrangler deploy --dry-run` to catch missing rebuilds.

## 7. Build integration: `scripts/build-gitea-assets.mjs`

The script (this file's sibling) implements exactly the proven §3 procedure:
copy the committed input set from `gitea/` into a work dir (default: a fresh
`os.tmpdir()` dir), `pnpm install --frozen-lockfile`, clean the output entries
(Makefile-equivalent), `pnpm exec vite build` with `ENABLE_SOURCEMAP=false`,
verify the manifest contains the required entries, then emit the tree
(`js/ css/ fonts/ img/ .vite/ licenses.txt emoji.json`, never `*.map`) into the
target dir (default `apps/worker/public/assets`). Parameters are documented in the
script header. It has **zero npm dependencies** (node:fs/child_process only) and
never writes inside `gitea/`.

## 8. Risks and mitigations

| Risk | Assessment | Mitigation |
|---|---|---|
| License | Gitea is MIT; bundles already ship `licenses.txt` aggregating JS+Go dep licenses (built from committed `assets/go-licenses.json`). We redistribute unmodified vendor assets | Keep `licenses.txt` in the served tree; record vendoring in NOTICE discipline |
| Bundle weight | Core page ≈ 969 kB (105 kB jQuery iife + 864 kB index closure incl. 255 kB CSS); full tree 13.9 MB but 275/280 entries are lazy feature chunks (mermaid 1.5 MB, swagger 1.5 MB, 3d-viewer, katex…) served only when used | Edge-served, immutable-cached, no Worker CPU; budget tracked per re-pin. Do not add heavy islands of our own |
| Fomantic/jQuery | CSS dependency on Fomantic is **gone** at this pin (Gitea-owned CSS); JS still needs jQuery 4 + the 2-file dropdown/api fork (bundled in `iife.js`, 105 kB). Upstream is actively shrinking jQuery usage | Our HTML only needs the `.ui.dropdown` DOM shape; expect `iife.js` to shrink on re-pins — no action for us |
| Re-pin coupling (ADR-0002/D5) | Asset hashes and manifest change with the submodule pin; template/DOM contract may drift upstream | Rebuild via `pnpm build:assets` at every re-pin (make it a checklist item); the DOM contract of §4 is small enough to re-verify by diffing the handful of templates listed there |
| Build inputs hiding in "committed" state | `public/assets/img/svg`, `emoji.json`, `assets/codemirror-languages.json`, `assets/go-licenses.json` are generated upstream but committed today; if upstream stops committing them, the standalone build breaks | The build script asserts input presence with per-file errors; re-pin checklist notes to run `node tools/generate-svg.ts` + `generate-codemirror-languages.ts` in a scratch copy if ever needed |
| DOM drift breaks enhancement silently | Missing `data-global-init`/`window.config` degrades pages without 404s | The footer's `frontendInited` alert already fires in prod; add a Tier-2 smoke test asserting `window.config.frontendInited === true` per shipped page |
| i18n | No client i18n bundles are needed: `window.config.i18n` carries 7 general keys; all page text is server-rendered | Hono JSX renders translated strings (sources: committed `options/locale/locale_*.json`); ship English first |
| CSP | Upstream templates use per-request script nonces (`ctx.CspScriptNonce`) | Tier-2 v1 can relax to hash/nonce-free policy or implement per-request nonces when we adopt CSP — decide in SPEC-0006 |
| web components | Only 4 at this pin (2 own, 2 deps), all inside index.js | None to serve separately; list re-checked at each re-pin |
